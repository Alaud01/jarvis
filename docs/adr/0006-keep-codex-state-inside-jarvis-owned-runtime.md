# Keep Codex state inside a Jarvis-owned runtime

Jarvis integrates ChatGPT subscription access through a bundled Codex app-server, but runs it with a dedicated `CODEX_HOME`, state database, working directory, and account lifecycle under Jarvis application data. Jarvis conversations remain the only user-visible conversation model and map to private app-server threads; Jarvis never reads, copies, or writes the user’s normal `~/.codex`, and one-off work uses ephemeral threads. This preserves the supported app-server protocol while avoiding the cross-client auth and thread overlap that would result from sharing the user’s Codex installation or state directory.

## Amendment: follow Codex Switcher's active account

When Codex Switcher is installed (`~/.codex-switcher/accounts.json` exists), Jarvis makes the private runtime's `auth.json` a symlink to `~/.codex/auth.json`, the file Codex Switcher rewrites when it changes accounts. Threads, state databases, and the working directory stay private; only the credential is shared. Codex rewrites `auth.json` in place and reloads it before refreshing a token, so Jarvis and the other Codex clients share rotated refresh tokens safely. The app-server caches auth in memory, so Jarvis restarts it whenever the active account id changes. If a turn fails on a usage limit after the account has changed, Jarvis retries it once on the new account. In this mode Jarvis never runs `account/login` or `account/logout`, because those would overwrite or revoke the Switcher-managed login. Set `JARVIS_CODEX_PRIVATE_AUTH=1` to keep the original private-login behavior; any earlier private login is preserved as `auth.json.jarvis-private`.
