# Bridge Jarvis tools into Codex with app-server dynamic tools

Jarvis exposes the same assistant tool catalog to Codex through app-server `dynamicTools`, while keeping tool execution and policy in the existing Jarvis-owned dispatcher. Other model providers retain their native function-calling loops, and Codex receives a namespaced, thread-scoped adapter whose calls return through `item/tool/call`; Jarvis does not run a second model turn or expose its tools through a separate MCP server. This keeps Browser Control, search, fetch, and Notion behavior consistent across providers without merging their protocol state, and Codex remains authenticated only through the user’s ChatGPT subscription rather than an OpenAI API key. Because the app-server dynamic-tool surface is experimental, Jarvis pins the bundled Codex version, fingerprints persisted tool schemas, and recreates private Codex threads when that schema changes.
